# All 28 `gmodule/rel_*.prx` modules — survey index

One survey per module, generated by `scripts/module_survey.py` (section table +
splat disassembly + printable strings in `.data`). Every module now has a
section-accurate splat config that covers **100% of its file**, so any of them
can be split and worked on immediately.

Each module also has its own branch, `module/<name>`, carrying that module's
config and survey doc. This branch (`survey/all-modules`) is the combined view.

## Cross-cutting findings

These are the reason for doing all 28 at once — each one is leverage that
applies to many modules rather than one.

**1. One NID table, 28 modules. — DONE, see `docs/nids/README.md`.** Every
module's `.rodata.sceNid` is ~0x1B04 bytes / 1729 entries with one 8-byte
`.sceStub.text` trampoline each. Those 1729 are **not** SDK imports (an earlier
version of this note said so and was wrong): they are the complete export list
of `libehsys_rel`, the engine in the EBOOT, which every module links a stub for
whether it calls it or not. The array is byte-identical in all 28 modules *and*
in the EBOOT's export table (`sha1 820088858e31`), so stub *k* is the same
engine function everywhere and the EBOOT pairs each NID with its address.

Resolved: **986** engine functions actually called project-wide, **275**
module-to-module imports, and **47** genuine `sce*` SDK imports (all
hash-verified against their names). `config/symbols/<module>.txt` now feeds
splat, so any module re-split gets named calls.

**2. A shared card-list widget is statically linked into six modules.** The
asset set `cis_all.gim`, `ciss.gim`, `panel.gim`, `icon01..icon06.gim`,
`spelltrap.gim`, `frame.gim` appears verbatim in `rel_conv_machine`,
`rel_deck`, `rel_deckswap`, `rel_limitlist`, `rel_recipeviewer` and
`rel_select_card`. Those modules almost certainly contain the *same* compiled
card-list code. Matching it once in the smallest carrier (`rel_limitlist`,
0x5878, or `rel_recipeviewer`) should transfer to the other five — including
`rel_deck`, which is 8x bigger.

**3. `jegfis` appears in the `.data` of ~10 unrelated modules.** Same string,
same position relative to other resource names. It is a shared format/resource
tag; identifying it once explains a chunk of the resource-loading path
everywhere.

**4. Language handling is 6-way and consistent.** `rel_title` ships
`option_msg_{j,e,g,f,i,s}.bin` — Japanese, English, German, French, Italian,
Spanish. That is exactly the 6-case jump table already decompiled in
`rel_html_view`'s `func_0000039C`, which maps the system language onto the
module's own id. The `strTbl_%c.bin` / `all_%c.ehp` / `%c.gim` pattern in a
dozen modules is the same language letter.

**5. Module convention holds everywhere.** Each `rel_X.prx` exports `libX_rel`
and imports `libehsys_rel` (the engine in the encrypted EBOOT). In 10 modules
the survey found `func_00000000` registering its callbacks the same way
`rel_movie_viewer` and `rel_html_view` do — entry point, main routine, teardown
hook. Expect the same 3-argument registration call to open every module.

**6. Small functions are not evenly spread.** `rel_duel_draw` has 595 functions
of <=16 words and `rel_story` has 336 — more trivially matchable functions than
the entire small-module tier combined. A "match all the accessors" pass over the
big modules may be cheaper per function than a whole small module.

## Suggested order

1. **Resolve the NID table** (finding 1) — it is worth more than any single module.
2. Finish `rel_html_view` and `rel_movie_viewer` (one function each remaining).
3. `rel_labo` (14 funcs) -> `rel_soundtest` (12) -> `rel_tutoriallist` (31) -> `rel_password` (41) -> `rel_debug_menu` (44) -> `rel_duelrecord` (47).
4. `rel_limitlist` to pin down the shared card-list widget (finding 2), then reuse it.
5. Bulk-match the <=16-word tier of `rel_duel_draw` / `rel_story` (finding 6).
6. `rel_duel_eng` last — but it is the actual goal, and the only place card logic exists.

## Re-running

```
scripts/module_survey.py rel_gallery              # config + split + doc
scripts/module_survey.py rel_gallery --no-split   # doc only, from existing asm/
```

`asm/` and `build/` are gitignored, so a fresh clone regenerates them from the
configs. The script restores `include/include_asm.h` after each run (splat
rewrites its include paths as a side effect of running from `config/`).
